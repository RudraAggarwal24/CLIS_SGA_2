Question 3: Secure File Processing Using Linux System Calls


Aim


The objective of this program is to implement a secure file-processing utility using Linux system calls instead of standard library functions. The program creates a file, writes employee records, updates a specific record without rewriting the entire file, retrieves records efficiently from any location, and closes the file properly.


--------------------------------------------------------------------------------


Problem Statement


A company requires a secure file-processing utility that uses Linux system calls for efficient file management. The program should create a file, store employee records, update a specific employee record without rewriting the complete file, retrieve records from any location using random access, and release all system resources after execution.

Linux System Calls Used


open()


Purpose:
Creates or opens a file and returns a file descriptor.


Contribution:
The program uses open() to create the employee data file and obtain a file descriptor that is used for all subsequent file operations.


--------------------------------------------------------------------------------


write()


Purpose:
Writes data to a file.


Contribution:
Employee records are written directly into the file using write(), allowing efficient storage of data.


--------------------------------------------------------------------------------


read()


Purpose:
Reads data from a file.


Contribution:
The program retrieves employee records from the file and displays them after reading.


--------------------------------------------------------------------------------


lseek()


Purpose:
Moves the file pointer to a specific location.


Contribution:
The program uses lseek() to directly access a required employee record and update it without rewriting the entire file. This enables efficient random access to records.


--------------------------------------------------------------------------------


close()


Purpose:
Closes the file descriptor.


Contribution:
After all file operations are completed, close() releases the file descriptor and ensures that all resources are freed properly.


--------------------------------------------------------------------------------


How the Program Solves the Problem


The program first creates the employee data file using open(). It stores employee records using write(). To retrieve a specific record, it moves the file pointer directly to the required location using lseek() and reads the record using read(). When updating an employee's salary, lseek() positions the file pointer to the exact record, allowing write() to overwrite only that record instead of rewriting the complete file. Finally, close() releases the file descriptor after all operations are completed.


--------------------------------------------------------------------------------


Theory


Linux system calls provide direct access to operating system services without relying on standard library functions. The open() system call creates or opens files and returns a file descriptor. The write() system call stores data in the file, while read() retrieves data from it. The lseek() system call moves the file pointer to any position, making random access and in-place updates efficient. The close() system call releases the file descriptor and associated resources after file operations are complete. These system calls provide better control, improved efficiency, and secure file handling in Linux applications.
