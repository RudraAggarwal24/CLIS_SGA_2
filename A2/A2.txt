Question 2: Process Management Using fork(), wait(), and Signals


Aim


The objective of this C program is to simulate process management in a Linux environment by creating child processes using fork(), monitoring their execution, preventing zombie processes, and terminating unresponsive child processes using appropriate signals. This demonstrates how a web server efficiently manages multiple client requests.


--------------------------------------------------------------------------------


Problem Statement


A web server may become unresponsive when excessive child processes are created or when terminated child processes are not properly cleaned up. This program demonstrates how to create, monitor, and safely terminate child processes while preventing zombie processes.


--------------------------------------------------------------------------------

System Calls Used


fork()


Purpose:
Creates a new child process.


Explanation:
The parent process creates three child processes using fork(). Each child process executes independently, allowing multiple tasks to run simultaneously.


--------------------------------------------------------------------------------


wait()


Purpose:
Waits for child processes to terminate and collects their exit status.


Explanation:
The parent process waits for completed child processes and removes them from the process table, preventing zombie processes.


--------------------------------------------------------------------------------


kill()


Purpose:
Sends a signal to another process.


Explanation:
The parent process sends a termination signal to stop the child process that becomes unresponsive.


--------------------------------------------------------------------------------


SIGTERM


Purpose:
Gracefully terminates a process.


Explanation:
SIGTERM requests the unresponsive child process to terminate safely, allowing it to release resources before exiting.


--------------------------------------------------------------------------------


How Process Creation, Waiting, and Signal Handling Work Together


The parent process first creates multiple child processes using fork(). It continuously monitors their execution while each child performs its assigned task. As child processes finish, the parent uses wait() to collect their exit status, preventing zombie processes from remaining in the process table. If a child process becomes unresponsive, the parent detects the problem and sends a SIGTERM signal to terminate it gracefully. Together, process creation, waiting, and signal handling ensure efficient process management, proper resource utilization, and reliable server performance.


--------------------------------------------------------------------------------


Theory


In Linux, a process is an executing instance of a program. The fork() system call creates child processes that execute independently of the parent. The wait() system call allows the parent to collect the termination status of child processes, preventing zombie processes from accumulating. Signal handling enables one process to communicate with another by sending signals such as SIGTERM to request graceful termination. Combining these mechanisms allows Linux to manage multiple processes efficiently while maintaining system stability.
